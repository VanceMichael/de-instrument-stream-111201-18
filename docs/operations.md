# 本地运行说明

先运行单元测试，再执行演示命令。演示从干净临时目录发起真实请求并处理响应，不需要外部站点。
常规导入失败时返回非零退出码，事务中的原文和记录会一起回滚，可保留源文件再次处理。
查询模式只读取当前数据库，不会补采或删除来源数据。需要长期保留证据时，请备份整个数据库。
本地响应服务支持状态码、响应头、文本或 base64 字节正文；未配置路径返回未找到。
每条路径的脚本独立推进，最后一个响应会重复；可借请求记录核对调用顺序。

## 连续流接收运维

接收器 `receive` 设计为长期进程，状态全部落在 SQLite（WAL 模式），重启后自动
接续。核对一次乱序补发时，先跑 `simulate`，再用 `stream` 查看四张表对应的状态：
`frames` 是实际入库的帧（含负载文本），`acks` 是每条确认及所属连接，
`gaps` 记录序号缺口与致命断开，`events` 按时间顺序记录连接、重同步、
入库/重复、断开等帧级事件，可完整复盘“究竟收了什么”。

- 正常读取：`simulate --mode normal`；故障注入：`simulate`（默认）或
  `--coalesce`（粘包）、`--garbage N`（垃圾洪泛）。
- 缓冲上限 8192 字节、最大负载 4096、连续重同步预算 16 次、工作队列 128 帧，
  均可通过 `receive` 的参数收紧；任何一项越界都会断开当前连接并写 `fatal_disconnect`。
- 确认只在帧事务提交后发出。看到 `unacked_frames` 非空表示进程曾在保存与确认
  之间退出；仪器重连补发时该帧幂等重存，不会产生重复行，确认随后补齐。
- 同一 `(epoch, sequence)` 永远只入库一次；新 epoch 是独立序号空间，
  设备重启后的首帧不会被旧代际的同序号帧误去重。
- 接收器只绑定回环地址；不要把原始 TCP 端口暴露到不可信网络。
数据文件的路径均相对项目根目录，修改工作目录前请确认输入和数据库参数。
